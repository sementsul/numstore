# ТЗ — numstore: реферальная витрина красивых номеров (API Безлимит)

> Проект личный, владелец = ПМ (сам пользователь, партнёр Безлимит id **800848**).
> Гейт «согласование с Денисом» здесь НЕ применяется (нет чужих денег/кастоди — см. «Ограничения»).

## Цель (зачем, какую проблему решаем)
Своя брендированная витрина красивых номеров, монетизация — **реферальная комиссия** Безлимит.
Пользователь заходит, смотрит/фильтрует номера, жмёт «купить» → уходит в реф-поток Безлимит с id 800848.

## Вход / выход (данные)
- **Вход:** публичный API Безлимит `https://api.store.bezlimit.ru/v2` (CORS открыт для любого домена).
  - `GET /super-link/phones/collection?expand=phones.tariff` → массив коллекций, в каждой `phones[]`.
  - `GET /super-link/phones/filters` → справочники фильтров (mask_category, mask_pattern, tariff, …).
  - Auth: заголовок `Authorization: Basic <token>` — токен публичный, захардкожен в бандле Безлимит.
  - Объект номера: `{ phone: 9584949494, type, type_category, tariff:{ name, group_name, price, minutes, sms, internet, … } }` (+ вложенные поля — цена номера/маска, добираем при вёрстке).
- **Выход:** статический сайт; каталог рендерится в браузере посетителя (его IP → бан не грозит).

## Функциональные требования (v1, по пунктам)
1. Клиентский fetch каталога из API Безлимит (в браузере посетителя, не на сервере/CI).
2. Список номеров с фильтрами: маска/паттерн, тариф, цена.
3. Карточка номера: сам номер, тариф (название, цена, минуты/смс/интернет).
4. Кнопка «купить/забронировать» → реф-поток Безлимит с id **800848** (точную атрибуцию покупки уточнить через Network на шаге брони — см. открытые вопросы).
5. Токен Basic **авто-извлекается на этапе сборки** из JS-бандла `l.bezlimit.ru` (этот хост не банит CI) + хардкод-фолбэк.

## Критерии готовности (как поймём, что готово)
- Открываешь сайт → грузятся реальные номера с ценами и тарифами.
- Фильтры работают (маска/тариф/цена).
- Кнопка «купить» ведёт в поток Безлимит с рефом 800848 (проверить, что покупка реально атрибутируется — критично для денег).
- Собирается статикой; деплой (предположительно GitHub Pages).

## Ограничения (стек, сроки, чего НЕ делаем)
- **Некастодиально:** НЕ храним деньги, НЕ храним чужие API-ключи, НЕ проводим сделки у себя. Кастодию и KYC держит Безлимит.
- Стек: статический фронт (HTML/CSS/JS; при необходимости лёгкий билд-скрипт на Python как в ratescout).
- 🔶 ПРИНЯТЫЙ РИСК: API недокументированный + токен чужой. Пересмотреть если: Безлимит сменит токен/эндпоинты/CORS. Митигируем авто-извлечением токена; по-хорошему — написать их партнёрской поддержке.
