# numstore — карта проекта (project-notes)

Реферальная витрина красивых номеров на API Безлимит. Партнёр id **800848**. Некастодиально.
Истина по задаче: `TZ.md`. Живые сценарии: `docs/numstore.usecases.md`.

## Что где
- `index.html` — разметка + контролы (поиск/тариф/сортировка).
- `config.js` — `API_BASE`, публичный Basic-токен Безлимит, реф-URL (`REF_STORE_URL`, `REF_ID`).
- `app.js` — клиентский fetch каталога, рендер карточек, фильтры/поиск/сортировка.
- `styles.css` — оформление.
- `docs/` — project-notes, usecases, DEFINITION_OF_DONE.

## Запуск / превью
- Статика: `python3 -m http.server 5173 --bind 0.0.0.0` в корне → http://localhost:5173.
- ⚠️ Каталог грузится в БРАУЗЕРЕ посетителя (его IP). Серверный/CI IP у `api.store.bezlimit.ru` в бане
  (анти-бот датацентров) — но клиенту это не мешает.

## Ключевые решения / грабли
- 🧭 **Некастодиально:** не храним деньги и чужие ключи; кастоди+KYC на Безлимит; реф-id при покупке. Легалка минимальна.
- 🧭 **Клиентский fetch, а не CI-скрейп:** `api.store.bezlimit.ru` банит датацентровые IP («banned permanently»).
  Обход анти-бота НЕ делаем. Читаем из браузера посетителя (чистый IP) — CORS у API открыт (проверено с example.com).
- 🧭 **Каталог глобальный:** `/super-link/phones/collection` отдаёт одинаковый набор без store-id; реф цепляется на покупке.
- 🔶 ПРИНЯТЫЙ РИСК: API недокументированный + токен чужой (публичный, из их бандла). Пересмотреть если Безлимит
  сменит токен/эндпоинты/CORS. Митигация: авто-извлечение токена из бандла `l.bezlimit.ru` на сборке (TODO) + фолбэк.
- 🧭 **git identity = `numstore-dev`** (НЕ личное имя владельца — публичный репо).
- 🔴 Атрибуция реф-покупки к 800848 — не подтверждена деньгами (пока редирект в общий реф-стор). Снять из Network.
