## Радиус проекта (что затронуто + соседи/роли)
- **Файлы:** `index.html` (разметка/контролы), `app.js` (fetch каталога + рендер + фильтры), `config.js`

## UC-1. Загрузка каталога (клиент, ban-proof) ✅
**Предусловие:** сайт открыт в браузере посетителя (его IP, не CI). **Шаги:** открыть `/`.
**Ожидаемо:** `app.js` делает `GET /super-link/phones/collection?expand=phones.tariff` с Basic-токеном,
сплющивает `items[].phones[]`, вместо «Загружаю номера…» рендерит карточки. **Проверка:** ручной тест в браузере.

## UC-2. Карточка номера ✅

## UC-6. Кнопка «Забронировать» → прямая бронь ✅
**Шаги:** нажать «Забронировать» на карточке → подтвердить диалог. **Ожидаемо:**
POST `/super-link/reservations?expand=super_link_uuid`, FormData `{phone, tariff_id, type:"store",
user_id:"800848", filter:"professional"}` → создаётся бронь на аккаунте партнёра (dealer 1165593, ~1ч),
из ответа берём `super_link_uuid.uuid` → открывается `store/800848?type=p&cubes=<номер>&uuid=<uuid>`.
Попап открываем в контексте клика (иначе блокировщик). Ошибка/лимит → alert с `message`.
✅ Атрибуция к 800848 подтверждена: `user_id:"800848"` в теле → `dealer_id:1165593` в ответе.
🔶 РИСК: каждый клик = реальная бронь из лимита 50 (авто-отмена ~1ч). Митигация: confirm перед бронью.

## UC-8. Поиск по маске (cubes) — живая подгрузка из API ✅
**Предусловие:** каталог показан. **Шаги:** заполнить ячейки маски (10 позиций): цифра — точная,
пусто → `N` (любая), буква `a/b/c…` — повторяющаяся цифра. **Ожидаемо:** с дебаунсом 500мс летит
`GET /super-link/phones/mask-category?expand=tariff&is_reserved=false&per_page=60&phone_pattern=<маска>`;
ответ — объект-группы `{"<категория>":{items:[номера]}}`, `extractPhones` вытаскивает номера из любой
структуры; показываются все подходящие (не только стартовые коллекции). Пустая маска → дефолтные коллекции.
✅ ПОДТВЕРЖДЕНО: параметр API = **`phone_pattern`** (НЕ `cubes` — тот API игнорирует), `N` = любая цифра,
10 позиций. Проверено: `9NNNNNNNNN`→все на 9 (250 шт.), `99NNNNNNNN`→все на 99 (211 шт.).
NB: в реф-ссылку на сайт Безлимит маска идёт как `cubes`, а в API-поиск — как `phone_pattern`.

## UC-12. Серверные фильтры: клик по категории/тарифу грузит номера из API ✅/❌
**Предусловие:** страница открыта. **Шаги:** кликнуть категорию/тариф в сайдбаре.
**Ожидаемо:** сайдбар строится из официального `/super-link/phones/filters` (`mask_category`:
[{name,filter:"brilliant,brilliant_super"…}], `mask_tariff`: [{name,filter:<id>}]). Клик → `fetchNumbers()`
собирает запрос `mask-category?phone_pattern=<маска|9NNNNNNNNN>&mask_categories=<код>&mask_tariff=<id>` и
подгружает номера с сервера (не фильтрует локальный пул). Цена (тир) — клиентский пост-фильтр. Сортировка +
«показать ещё» + бронь работают. **Радиус:** app.js (loadFilters/buildSidebar/fillList/fetchNumbers/matchesPrice),
index.html (#fCat/#fPrice/#fTariff), styles.css (.filter-*).
✅ Категория — серверная (`mask_categories`, из бандла). Тариф — КЛИЕНТСКИЙ фильтр (по `tariff.id` в загруженном
пуле): проверено — `mask_tariff`/`mask_tariffs`/`tariffs`/`tariff` на mask-category НЕ фильтруют (все вернули 200
со всеми тарифами). Категории — живьём из `/filters`. Тарифы — **строятся из фактически загруженных номеров** (`buildTariffFilter`
из ALL, сорт по цене): в /filters есть мёртвые тарифы (ULTRA 550/399 — 0-1 номер), в сайдбаре показываем
только те, по которым есть номера. При смене тарифов Безлимитом обновятся сами. Цена — клиентский пост-фильтр.
Заменяет клиентские фильтры UC-11.
